# بسته اصلاحی سامانه دیده‌بان — نسخه 2.1

## فایل‌ها
- `index.html`: نسخه کامل سایت بر پایه آخرین فایل ارسالی کاربر (`index(4)(2).html`)؛ فقط بخش موتور تحلیل/نمایش خطا و کنترل تکراری ثبت تأیید به‌روزرسانی شده است.
- `supabase/functions/didehban-ai-documents/index.ts`: نسخه کامل Edge Function با همان نام فعلی.

## ترتیب استقرار
1. از فایل فعلی سایت یک نسخه پشتیبان نگه دارید.
2. در Supabase → Edge Functions → `didehban-ai-documents` → کد تابع، تمام محتوای فایل `index.ts` را جایگزین کنید و Deploy بزنید.
3. در هاست سایت، فایل `index.html` داخل همین بسته را جایگزین نسخه فعلی کنید.
4. هیچ SQL migration یا تغییر Secret برای این نسخه لازم نیست؛ نام Secretهای فعلی دست‌نخورده می‌ماند.
5. پس از Deploy، یک سند آزمایشی کوچک (ترجیحاً PDF متنی یا XLSX کوتاه) را ابتدا استخراج و سپس با Gemini تحلیل کنید. قبل از «تأیید و ذخیره»، JSON خروجی را بررسی کنید.

## Secretها
این کد از موارد زیر استفاده می‌کند:
- `SUPABASE_URL` و یکی از `SUPABASE_ANON_KEY` یا `SUPABASE_PUBLISHABLE_KEY` (متغیرهای محیطی Supabase)
- `GEMINI_API_KEY` (الزامی)
- `GEMINI_MODEL` (اختیاری؛ مقدار پیش‌فرض در کد فعلی `gemini-3.5-flash-lite`)
- `GEMINI_FALLBACK_MODELS` (اختیاری؛ جداکننده مدل‌ها ویرگول انگلیسی است)
- `GEMINI_BACKUP_API_KEY` (اختیاری؛ کلید پشتیبان مستقل)
- `ALLOWED_ORIGIN` (اختیاری؛ برای CORS)

هیچ API key را داخل `index.html` قرار ندهید و کلیدهای واقعی را در اختیار کسی نگذارید. این نسخه Secretهای فعلی را تغییر نمی‌دهد.

## اصلاحات این نسخه
- رفع مسیر بازیابی بخش cache‌شده: وقتی همه بخش‌ها قبلاً پردازش شده‌اند، خروجی ادغام‌شده از جدول والد برگردانده/در صورت لزوم بازسازی و ذخیره می‌شود؛ خروجی آخرین chunk به‌اشتباه جای کل سند نمایش داده نمی‌شود.
- پاسخ نهایی `model` را در کنار `models` برمی‌گرداند تا نام مدل در رابط نمایش داده شود.
- جزئیات خطا، مرحله پردازش، شناسه پیگیری و وضعیت HTTP ارائه می‌شود؛ فرانت‌اند متن پاسخ خطای Edge Function را می‌خواند، نه فقط پیام عمومی `non-2xx` را.
- بخش ناموفق در جدول بخش‌ها با وضعیت `failed` و پیام خطای تشخیصی علامت‌گذاری می‌شود؛ اجرای مجدد همان بخش آن را دوباره پردازش می‌کند.
- پس از تأیید، اگر درج به‌علت محدودیت یکتایی تکراری باشد، رکورد قبلی با هش سند بازیابی می‌شود.
- محدودیت‌های اصلی دیتابیس و نام جدول‌ها/ستون‌ها با خروجی ساختار و Constraints ارسالی بررسی شده‌اند؛ migration جدیدی افزوده نشده است.

## دامنه و محدودیت‌ها
- این نسخه هنوز نیازمند تست واقعی روی پروژه Supabase و یک فایل آزمایشی است. از اینجا امکان Deploy به پروژه شما یا تست زنده با کلیدهای شما وجود ندارد.
- Policy فعلی `memberships_insert_self` در خروجی ارسالی فقط `user_id = auth.uid()` را بررسی می‌کند. این Policy می‌تواند امکان عضویت‌سازی غیرمجاز را ایجاد کند. در این بسته دست‌نخورده مانده تا جریان ساخت شرکت/دعوت کاربران بدون بررسی کامل شکسته نشود؛ پیش از استفاده عمومی باید با منطق دعوت و مالکیت شرکت اصلاح شود.
- این نسخه استخراج ساختاریافته و تأیید انسانی را انجام می‌دهد؛ مدل یادگیری ماشین آموزش‌دیده برای پیش‌بینی تأخیر در آن فعال نشده است.
