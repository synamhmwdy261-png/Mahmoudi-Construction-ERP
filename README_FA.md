# بسته یکپارچه‌سازی هوش مصنوعی دیده‌بان

این بسته شامل رابط وب، تابع امن اتصال به OpenAI از طریق Supabase Edge Functions و جدول مرکزی پیش‌نویس‌های استخراج‌شده است.

## آنچه در این بسته پیاده‌سازی شده
- رابط مرکز اسناد برای اجرای تحلیل ChatGPT روی متن استخراج‌شده
- فراخوانی OpenAI فقط از سمت سرور؛ کلید OpenAI در HTML قرار نمی‌گیرد
- بررسی نشست کاربر و عضویت او در شرکت قبل از تحلیل
- خروجی ساختاریافته برای مشخصات سند، نفرات، فعالیت‌ها، ماشین‌آلات، مصالح، موانع و برنامه روز بعد
- نمایش JSON قابل ویرایش قبل از ذخیره
- ذخیره خروجی تأییدشده در جدول `ai_document_records`
- RLS برای جداسازی داده شرکت‌ها بر اساس جدول `memberships`

## پیش‌نیاز
- پروژه Supabase فعلی دیده‌بان
- Supabase CLI نصب‌شده و دسترسی Deploy به همان پروژه
- کلید API سرویس OpenAI
- فعال بودن Auth و جدول‌های `companies` و `memberships` در پروژه فعلی

## نصب روی Supabase
از ریشه همین بسته:

1. فایل `database.sql` را در SQL Editor پروژه Supabase اجرا کنید.
2. در تنظیمات Function Secrets این متغیرها را ثبت کنید:
   - `OPENAI_API_KEY` = کلید محرمانه OpenAI
   - `OPENAI_MODEL` = `gpt-4.1-mini` (اختیاری؛ مقدار پیش‌فرض همین است)
   - `ALLOWED_ORIGIN` = دامنه دقیق سایت دیده‌بان (برای انتشار تجاری تنظیم شود؛ مقدار پیش‌فرض `*` فقط برای راه‌اندازی اولیه است)
3. متغیرهای سیستمی Supabase یعنی `SUPABASE_URL` و `SUPABASE_ANON_KEY` باید در محیط Edge Function موجود باشند. کلیدهای محرمانه را هرگز در مرورگر یا فایل HTML قرار ندهید.
4. تابع را Deploy کنید:

```bash
supabase functions deploy didehban-ai-documents
```

5. فایل `index.html` را در هاست فعلی وب دیده‌بان جایگزین کنید. قبل از انتشار عمومی، روی نسخه آزمایشی و با یک شرکت آزمایشی تست شود.

## جریان استفاده
1. کاربر وارد دیده‌بان می‌شود و شرکت را انتخاب می‌کند.
2. فایل را انتخاب و متن آن را استخراج می‌کند.
3. «تحلیل با ChatGPT» را می‌زند.
4. JSON استخراج‌شده را بررسی و اصلاح می‌کند.
5. با تأیید، رکورد در `ai_document_records` ذخیره می‌شود.

## محدودیت‌های فعلی و کارهای لازم پیش از فروش
- PDF/تصویر/Excel/DOCX در این نسخه ابتدا در مرورگر به متن تبدیل می‌شوند؛ برای اسناد بزرگ، دست‌نویس و حجم بالا باید صف پردازش سمت سرور و OCR تخصصی اضافه شود.
- تابع فعلی متن هر فایل را تا ۹۰ هزار نویسه می‌پذیرد؛ اسناد بزرگ‌تر باید chunk شوند و با شناسه سند به هم متصل شوند.
- خروجی در مخزن مرکزی اسناد هوشمند ذخیره می‌شود؛ هنوز adapter نهایی برای نوشتن مستقیم و تراکنشی در فرم‌های گزارش روزانه، انبار، صورت‌وضعیت و claims ساخته نشده است. این کار به schema واقعی هر ماژول وابسته است و نباید با حدس به جدول‌های موجود نوشت.
- اتصال Drive/OneDrive، پردازش صوت/ویدئو و فایل‌های CAD/BIM در این بسته فعال نیست.
- RAG/pgvector، پایش هزینه و سهمیه مصرف هر شرکت، ثبت کامل audit log، پشتیبان‌گیری و آزمون نفوذ باید پیش از بهره‌برداری تجاری تکمیل شوند.
- از بارگذاری اطلاعات محرمانه پروژه در هاست عمومی یا محیط آزمایشی بدون مجوز خودداری کنید.

## نکته امنیتی
کلید OpenAI و Service Role فقط در Secrets سمت سرور نگهداری شوند. کلید publishable/anon موجود در رابط وب مجوز دسترسی نیست؛ امنیت داده باید با RLS و بررسی عضویت سمت سرور اعمال شود.
